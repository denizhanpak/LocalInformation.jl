Internals

These are not exported and may change. Every local measure is built from LocalInformation.local_subset_entropies.

Local subset entropies

LocalInformation.local_subset_entropies — Function
LocalInformation.local_subset_entropies(est, x...; backend = CPU(), precision = nothing) → H

The internal core of the package. Return a callable H such that H(S) is a host Vector{T} of length N (the number of samples or encoded symbols) holding the local joint Shannon entropies $h(x_S)_i = -\log \hat p(x_S)_i$ of the inputs x[S], in the unit est.definition.base, with T = LocalInformation.resolve_precision(backend, precision). mean(H(S)) equals the estimate of the joint entropy of x[S] that Associations.jl uses for est (e.g. Associations.subset_entropies(est, x...)(S)).

H is directly usable as the entropy callable of Associations.entropy_combination (local higher-order measures) and to build local mutual informations, e.g. H((1,)) + H((2,)) - H((1, 2)).

The callable

  • S is a Tuple, Vector or range of distinct indices in 1:length(x); order does not matter. H(S) for an empty S returns zeros(T, N).
  • Results are cached per subset (sorted index vector), so repeated calls are cheap. The returned vectors are the cached objects: do not mutate them. H is not safe to call concurrently from several tasks.
  • The concrete type is LocalInformation.LocalSubsetEntropies.

Methods

  • JointProbabilities with CodifyVariables and the default RelativeAmount probabilities: plug-in local entropies from counts of the joint outcomes of x[S], with the same encoding as Associations.counts(est.discretization, x...). CPU.
  • EntropyDecomposition with PlugIn(Shannon()): the same, with the encoding of Associations.codified_marginals(est.discretization, x...). CPU.
  • EntropyDecomposition with Kraskov or KozachenkoLeonenko: k-NN local entropies of StateSpaceSet(x[S]...), using LocalInformation.knn_distances.
  • GaussianDecomposition, GaussianMI, GaussianCMI: Gaussian local entropies (see LocalInformation.local_gaussian_entropies). CPU or GPU.

Extending

A new estimator family adds one method

function LocalInformation.local_subset_entropies(est::MyEstimator, x...; backend = CPU(), precision = nothing)
    T = LocalInformation.resolve_precision(backend, precision)
    N = ...                                   # number of local values
    h(S::Vector{Int}) = ...                   # Vector{T} of local entropies, unit est.definition.base
    return LocalInformation.LocalSubsetEntropies{T}(h, N)
end

after which local_association works for its higher-order definitions, MIShannon and CMIShannon (see higher_order.jl and bivariate.jl).

LocalInformation.LocalSubsetEntropies — Type
LocalInformation.LocalSubsetEntropies{T}

The callable returned by LocalInformation.local_subset_entropies. H(S) returns the Vector{T} of local joint entropies of the inputs with indices S, computed by H.h(key) for the sorted subset key::Vector{Int} and cached. H(()) (empty subset) returns zeros(T, H.N), the additive zero required by Associations.entropy_combination.

LocalInformation.local_knn_entropies — Function
LocalInformation.local_knn_entropies(X, k, w, backend, T; metric = Euclidean(), estimator = :kraskov) → Vector{T}

Local k-NN entropies, in nats, of the points X (StateSpaceSet, vector or D × N matrix): -ψ(k) + ψ(N) + log V_D + D log ρ_i for estimator = :kraskov, and D log ρ_i + log V_D + γ + log(N - 1) (with k = 1) for estimator = :kozachenkoleonenko, where V_D is the unit-ball volume of metric. Kraskov and KozachenkoLeonenko (ComplexityMeasures) always use Euclidean().

Nearest neighbours

LocalInformation.knn_distances — Function
knn_distances(points, k::Integer, w::Integer = 0; metric = Euclidean(), backend = CPU(), precision = nothing) → Vector{T}
knn_distances(backend, P::AbstractMatrix, k::Int, w::Int, metric, T) → Vector{T}

Distance from every point to its k-th nearest neighbour, excluding the neighbours j of point i with abs(i - j) ≤ w (a Theiler window; w = 0 excludes only the point itself). Returned as a host Vector{T} in the order of the points.

points is a StateSpaceSet, an AbstractVector (a 1-D variable) or a D × N matrix whose columns are the points. metric is a Distances.jl metric (Euclidean(), Chebyshev(), ...).

The second, positional form is the backend-dispatched implementation called by the first, with P a D × N host matrix (Float64, one column per point) and T = LocalInformation.resolve_precision(backend, precision). The CPU method uses a NearestNeighbors.KDTree (in Float64, converted to T); any other KernelAbstractions backend (a GPU) uses the exact brute-force kernel LocalInformation.gpu_knn, in precision T and for the metrics Euclidean(), Chebyshev() and Cityblock().

LocalInformation.kth_neighbours — Function
LocalInformation.kth_neighbours(backend, P::AbstractMatrix, k, w, metric, T) → (dists, idxs)

Distance to and index of the k-th nearest neighbour of every column of P outside the Theiler window w. The CPU method searches a KDTree point by point, as Neighborhood.bulksearch(tree, points, NeighborNumber(k), Theiler(w)) does in Associations (so ties are resolved identically); the GPU method is LocalInformation.gpu_knn.

LocalInformation.ksg_counts — Function
LocalInformation.ksg_counts(est, x...; backend = CPU(), precision = nothing) → Vector{Vector{Int}}

The per-sample neighbour counts behind the local values of est, one vector per term:

  • KSG1: $n_m(t)$ for every marginal m (≤ ε_t, the point itself included);
  • KSG2: $θ_m(t)$ for every marginal m (≤ ε_m(t), the point itself excluded);
  • FPVP: $[n_{xz}, n_{yz}, n_z]$ (≤ ε_t, the point itself included).

On a GPU in Float32, a distance that ties with (or rounds across) a radius can shift a count by one relative to the Float64 CPU computation.

source
LocalInformation.gpu_knn — Function
LocalInformation.gpu_knn(backend::KernelAbstractions.Backend, P::AbstractMatrix, k, w, metric, T) → (dists::Vector{T}, idxs::Vector{Int})

Exact brute-force search on backend, in precision T: for every column i of the D × N matrix P, the distance to and the index of its k-th nearest neighbour among the columns j with abs(i - j) > w. Ties in distance are broken by the lower index. metric is Euclidean(), Chebyshev() or Cityblock().

source
LocalInformation.gpu_range_counts — Function
LocalInformation.gpu_range_counts(backend::KernelAbstractions.Backend, P::AbstractMatrix, r::AbstractVector, metric, T) → Vector{Int}

For every column i of the D × N matrix P, the number of columns j (including i itself, and with no Theiler window) at distance ≤ r[i] from it, computed on backend in precision T. Same semantics as NearestNeighbors.inrangecount(KDTree(P, metric), P[:, i], r[i]).

PID

LocalInformation.PIDCounts — Type
LocalInformation.PIDCounts

Plug-in counts for a PID of n sources and a target, per distinct joint state of all the inputs (K states, N samples). Source set M is the bitmask of Associations' redundancy lattice (source i is bit i - 1).

  • state[i]: the joint state (1:K) of sample i; weight[s]: its number of samples.
  • src[s, M]: number of samples whose sources in M have the values of state s.
  • srct[s, M]: the same, jointly with the target.
  • tgt[s]: number of samples with the target value of state s.

Counts are stored as Float64 (exact for counts below 2⁵³), so that inclusion–exclusion sums are matrix products.

source
LocalInformation.PIDLatticeData — Type
LocalInformation.PIDLatticeData

Data derived once per number of sources n from Associations' (shared, never modified) redundancy_lattice(n):

  • sx: the (2ⁿ - 1) × m inclusion–exclusion coefficients of ISx: $P(a_1 \cup \ldots \cup a_k) = \sum_M$ sx[M, node] $P(x_M)$, with sx[M, node] $= \sum_{J \subseteq \alpha,\, \bigcup J = M} (-1)^{|J|+1}$.
  • zeta: the zeta matrix of the lattice in the order lattice.order, zeta[a, b] = 1 if node order[a] ≼ node order[b]. It is unit upper triangular, and the atoms are $A = R Z^{-1}$ for local redundancies R (one column per node, in that order).
